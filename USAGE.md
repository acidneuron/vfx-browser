# VFX Asset Browser — User Guide

**Version:** Stage 01 · **Date:** 2026-10-12 · **Platform:** Windows 11

A local-first VFX asset browser. It indexes the media folders you already have,
generates instant thumbnails and short video proxies, and gives you search,
filters, metadata, favorites, and copyable file paths — **without ever touching
your originals.**

---

## 1. Requirements

| Requirement | Notes |
|---|---|
| Windows 10/11 | Tested on Windows 11 |
| Python 3.12+ | Any build; a venv is created for you |
| FFmpeg + ffprobe on PATH | Used for metadata and previews. Verify with `ffmpeg -version` |
| `uv` | Only needed for the initial setup (creates the venv) |

## 2. Setup & First Run

Everything lives in `C:\Users\User\vfx-browser\`.

```bat
:: one-time setup (already done in this installation)
uv venv .venv
uv pip install -r requirements.txt

:: start the server
run.bat
```

`run.bat` starts the backend. Then open **http://127.0.0.1:8765** in your browser.
The server runs in the console window that `run.bat` opens — close that window to
stop the server (the database and previews are on disk, so nothing is lost).

### Adding your first library

1. In the sidebar, type the path of a media folder into **Add root** (e.g. `D:\projects\showA\fx`) and press Enter.
2. The folder is scanned in the background: files are grouped, image sequences
   are collapsed into a single pattern, and metadata + thumbnails + proxies are
   generated by 2 background workers.
3. The status line at the top shows progress (`scanning…`, `N jobs`, `N ready`).
   Cards appear as soon as their thumbnail is ready — no need to wait.

You can add as many roots as you like; each is listed in the sidebar with its
asset count.

## 3. The Grid

- **Cards** show the thumbnail, name, and a meta line (kind, dimensions, format,
  frame count / duration, alpha).
- **Hover a card** and the short proxy video plays *in place* of the thumbnail
  (for videos and sequences). No expansion, no layout shift.
- **Click a card** to open the inspector.
- **Card size slider** (top right) adjusts the grid density live.
- Assets that are **missing on disk** are hidden by default (see *Library → Missing files*).
- Assets whose processing **failed** (e.g. corrupt video) still show, with an error line in the inspector.

## 4. Search & Filters

| Control | Effect |
|---|---|
| **Search box** | Matches name, tags, and category (substring, case-insensitive). Debounced as you type. |
| **Kind** | All / video / image / sequence |
| **Format** | By extension (exr, png, mp4, mov, jpg, …) — populated from what's actually in the library |
| **Alpha** | All / has alpha / no alpha / unknown. "Unknown" = probe failed; it is never reported as "no alpha" |
| **Min width** | Filter by minimum pixel width |
| **Sort** | Recent (default) / name / size / mtime / duration |

Filters combine with each other (AND logic).

### Library quick views (sidebar)

| Button | Shows |
|---|---|
| **All assets** | Everything — resets every filter |
| **Favorites** | Only favorited assets |
| **Recent** | Sorted by first-seen date |
| **Missing files** | Only assets whose file is gone from disk |

### Categories & roots (sidebar)

- **Categories** are derived from the folder structure (e.g. `Explosions`, `Smoke`).
  Click one to filter by category.
- **Roots** (e.g. `test_library`) filter to one library folder.
- Clicking any category/root clears the other navigation filters, so views never
  stack unexpectedly. **All assets** always brings you back.

## 5. The Inspector

Click any card. The inspector shows:

- **Large preview** — proxy video (videos/sequences) or preview image, with
  alpha composited over a checkerboard.
- **Metadata** — kind, format, dimensions, frame rate, duration / frame range
  (sequences show `start – end (pad N)`, plus missing frames if any), bit depth,
  alpha, channels, size, category, and timestamps.
- **Actions**

| Button | What it does |
|---|---|
| 📋 **Copy path** | Copies the absolute path (for sequences: the canonical `dir/base.%04d.ext` pattern) to the clipboard — paste it into Nuke's `Read` node or anywhere else |
| 🔄 **Reprocess** | Deletes this asset's cached previews and regenerates them (use after a source file changes on disk) |
| 📂 **Reveal in Explorer** | Opens the file's folder in Windows Explorer with the file selected |
| ▶ **Open in viewer** | Opens the file in the default application |
| ☆/★ **Favorite** | Toggles the favorite flag |

- **Tags** — comma-separated free text; saved when you leave the field
  (used by the search box).
- **Path box** — root path + full file path for copy-paste.
- **Close** — X button or `Esc`.

## 6. Keyboard Shortcuts

| Key | Action |
|---|---|
| `←` `→` `↑` `↓` | Move card focus (grid-aware) |
| `Enter` | Open inspector for the focused card |
| `Esc` | Close inspector |
| `f` | Toggle favorite on the focused card |

## 7. Background Processing

- Each asset goes through a 3-step pipeline run by **2 background workers**:
  **metadata → thumbnail → proxy**.
- **New files** in a watched folder are picked up automatically (watchdog) —
  no manual action needed.
- **Rescan button** (sidebar) forces a full rescan of all roots.
- The **status line** shows scan progress, jobs done/failed, and ready count.
- Everything survives restarts: the database and cached previews are on disk.
  Restarting the server does **not** regenerate previews.

## 8. Failure & Recovery

| Situation | Behavior |
|---|---|
| File deleted/moved from disk | Marked **missing** on next scan/watch; hidden from the grid; listed under **Library → Missing files**. Its previews are kept. Restore the file + rescan → back to normal. |
| Corrupt/unsupported media | Job fails with the exact error (e.g. `moov atom not found`); asset still shows, with the error in the inspector. |
| A job fails transiently | Click **🔄 Reprocess** on that asset, or hit `POST /api/jobs/retry-failed` (retries up to 3 attempts per asset). |
| Server killed mid-job | Interrupted jobs are recovered on next start; nothing is re-processed unnecessarily. |
| Source file changed on disk | **🔄 Reprocess** regenerates its previews. |

## 9. What Gets Stored Where

```
vfx-browser/
├── data/vfx.db     # the catalog: roots, assets, jobs (the only app state)
├── cache/          # derived files ONLY — safe to delete (regenerated on rescan)
│   ├── thumbs/     #   480px thumbnails
│   ├── previews/   #   1280px previews (alpha over checkerboard)
│   ├── proxies/    #   480px, ≤4s video proxies
│   └── checker.png #   alpha checkerboard
└── test_library/   # example synthetic library (not required)
```

**Your originals are never modified, moved, or copied.** The browser only
references them in place.

## 10. API Reference (for scripting/automation)

Base URL: `http://127.0.0.1:8765`

| Method & path | Purpose |
|---|---|
| `GET /api/status` | Library/job/scan status |
| `GET /api/roots` | List roots |
| `POST /api/roots` `{"path": "D:/..."}` | Add a root (starts scan) |
| `POST /api/roots/{id}/rescan` | Rescan one root |
| `GET /api/assets?` | List/filter assets. Params: `q_`, `kind`, `format`, `alpha` (`yes/no/unknown`), `min_w`, `category`, `root`, `fav`, `missing_only`, `sort`, `page`, `limit` |
| `GET /api/asset/{id}` | Full asset record |
| `POST /api/asset/{id}` `{"tags":…, "notes":…, "favorite":0/1, "fps":…}` | Update fields |
| `POST /api/asset/{id}/action` `{"action": …}` | `copy_path`, `nuke_path`, `reveal`, `open`, `fav`, `reprocess` |
| `GET /api/asset/{id}/thumb` · `/proxy` · `/preview` | Derived files (202 while pending) |
| `GET /api/facets` | Formats + categories present in the library |
| `POST /api/jobs/retry-failed` | Requeue failed jobs (cap 3 attempts) |

## 11. Troubleshooting

| Symptom | Fix |
|---|---|
| Port 8765 busy | Stop the other instance, or edit the port in `main.py` |
| `ffmpeg not found` in job errors | Install FFmpeg and ensure it's on PATH; then **Reprocess** the failed assets |
| Grid empty after a filter | Click **All assets** — it resets every filter |
| Previews look stale after a source change | **Reprocess** the asset |
| Server won't start | Run `run.bat` and read the console; log also in `server.log` if launched detached |
